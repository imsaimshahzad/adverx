# Project structure

This repository uses the existing framework conventions; avoid moving files just for cosmetic grouping because routes, generated files, and deployment config rely on known paths.

```text
adverx/
├── public/                         # Static assets served as-is
├── src/
│   ├── routes/                     # TanStack file-based pages and API routes
│   ├── components/                 # Shared app components
│   │   └── ui/                     # Reusable UI primitives
│   ├── integrations/supabase/      # Supabase clients, auth middleware, generated types
│   ├── lib/                        # Domain services, validation, formatting, utilities
│   ├── hooks/                      # Shared React hooks
│   ├── routeTree.gen.ts            # Generated; never edit by hand
│   ├── router.tsx                  # Router setup
│   ├── server.ts                   # Server entry / error handling
│   └── styles.css                  # Global styles
├── supabase/
│   ├── migrations/                 # Canonical Supabase SQL migration history
│   └── functions/                  # Supabase Edge Functions
├── drizzle/
│   ├── migrations/                 # Separate Drizzle migration history
│   └── schema.ts                   # Drizzle schema entry
├── docs/                           # Project and engineering documentation
├── package.json                    # Scripts and dependencies
├── vite.config.ts                  # Vite/TanStack build configuration
├── tsconfig.json                   # TypeScript and @/ path alias
└── .gitignore                      # Local/generated files excluded from Git
```

## Where new code belongs

- **Pages, layouts, route handlers:** `src/routes/`; keep route filenames compatible with TanStack file-based routing.
- **Reusable visual components:** `src/components/`; UI primitives stay in `src/components/ui/`.
- **Business/domain logic:** `src/lib/`. Keep database writes and financial rules server-side or in guarded database functions, not in presentation components.
- **Supabase clients and auth integration:** `src/integrations/supabase/`.
- **Database changes:** new timestamped SQL migrations in `supabase/migrations/`. Never edit an already-applied migration to change production state.
- **Static images/icons/manifest:** `public/`.
- **Generated route tree and temporary framework output:** generated by tooling; do not hand-edit or commit temporary output.

## Migration safety

The repository has both Supabase SQL migrations and Drizzle migrations. They are **not interchangeable**. Keep each history in its current directory. Because production migration history may differ from the Git history, reconcile it by comparing actual schema and migration contents before attempting any bulk renames, replay, or baseline operation.

## Generated and local artifacts

- `.tanstack/tmp/` is temporary router output and should not be versioned.
- `.wrangler/deploy/` is generated deployment metadata and should not be versioned.
- `.attached-lovable/` is a tool-generated project snapshot currently present in the repository. Treat the root-level files as the canonical deployable app; do not copy edits between the snapshot and root automatically. Remove the snapshot only after confirming the connected editor no longer depends on it.
